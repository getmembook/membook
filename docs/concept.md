# Membook — Founding Concept Document

**Name:** Membook — the memory book: a record written down, reviewed, and kept true. Settled after research eliminated Lore (Epic Games's Lore VCS), Lorekit (existing same-name MCP project), and Orma (trademarked AI-memory app + npm squat); Membook and the Sanskrit tier (Samskara, Smruti, Smarak) remain documented fallbacks. Existing "Membook" uses (a Finnish association-management SaaS, a retired AR photo app) are categorically distant. npm `membook` and `membook-mcp` verified free July 2026 — register immediately. CLI binary: `membook`. Repo directory: `.membook/`.
**One-liner:** Membook is a verifiable memory engine for coding agents — memory anchored to the code graph, invalidated by reality, auditable by design, shared across every agent, repo, and teammate.
**Status:** Concept v2.0 — July 2026, revised after deep research validation
**License:** MIT (core), commercial self-hosted tier (org graph)

---

## 1. Vision

Coding agents are amnesiacs, and where they are not amnesiacs they are unreliable narrators. Every session begins from zero unless memory is bolted on, and every bolted-on memory system in the market today shares a fatal flaw: it is text that nothing keeps honest. A memory that says "we use Jest" survives the migration to Vitest and is served to the agent as fact — and published research now quantifies what that costs: contaminated context raises per-step error rates roughly sevenfold and multiplies the cost of task completion several times over. Agents forget, and worse, they misremember.

Membook's thesis is that the next generation of agent memory must be **verifiable and auditable**. A memory is not a floating sentence; it is a claim anchored to checkable reality — a commit, a file, a symbol, an API contract, a dependency edge — so that when reality changes, the memory knows it. And a memory is not a database row; it is a reviewable file that travels in git, survives pull-request review, and can be shown to an auditor. Verification is the technical moat; auditability is the commercial one. Both fall out of the same design.

The engine has three planes bound by a verification loop. The **structural plane** models what the code and the organisation are: symbols, dependencies, and cross-repo edges — service contracts, shared libraries, infrastructure, ownership, approval gates. The **experiential plane** holds what was learned: decisions, gotchas, conventions, dead-ends, process knowledge, distilled from agent sessions and human input. The **verification plane** binds them: every memory anchors into the graph, so any change to the graph — in any connected repo — identifies exactly which memories are implicated, flags them stale, and triggers re-verification. The code graph is the skeleton, memories are the flesh, verification is the immune system.

## 2. What the Research Changed (v1 → v2)

This revision incorporates a full research validation pass, and three findings materially changed the plan. Honesty about them is the point of this section.

**The token-savings pitch is dead.** The original economics led with tokens saved (~90k per developer-week). The token *count* survived scrutiny, but the dollar translation did not: with prompt caching priced at roughly a tenth of base input cost, the tokens Membook saves are the cheap ones. For a 50-developer team, raw API savings land between roughly $75 and $3,500 per year — a rounding error against per-developer agent spend of $150–$2,000 per month. The value was always one layer up: **prevented wrong-path loops and reclaimed engineering hours.** Published evidence (context-contamination studies showing ~7× per-step error inflation from failed attempts, retry loops multiplying cost-per-task ~5×, and 21% more tasks resolved on the same budget with clean context) supports a time-and-error model in which the expected case for a 50-developer team is on the order of $130,000 per year of recovered engineering value. Membook's marketing and its metrics now speak in loops prevented and hours reclaimed, never in tokens.

**The single-user product is being commoditised in real time.** Claude Code auto-memory has shipped default-on; Codex Memories has shipped with cloud persistence announced; Cursor and Windsurf have rules and memories. All native memory remains single-tool, single-user, and unverified — but it is free and zero-setup, and it absorbs most of the casual value of a v1 single-repo tool. Separately, EverMind's EverOS proved to be a near architectural twin of our storage layer (markdown-first canonical memory, SQLite state, hybrid retrieval, local-first, Apache 2.0) with published benchmark scores. Conclusion: **the storage design is sound but not novel, and v1 is a wedge, not a business.** The defensible assets are the verification loop — which the research confirmed no player in any camp has shipped or announced — and the compliance-shaped trust model.

**The regulated-enterprise angle is stronger than assumed.** Financial-services sources map almost line-by-line onto Membook's design: SEC 17a-4, FINRA 4511, SR 11-7, NYDFS 500, and DORA all demand auditable, tamper-evident, inspectable records and favour self-hosted deployment; analysts note that self-hosting for a 100-developer regulated team can justify on the order of $30k/month because the alternative is not a cheaper cloud licence but no AI assistance at all. Committed, PR-reviewed, provenance-carrying `.membook/` files are examiner-ready in a way no cloud memory API can be. The org-graph server for regulated teams is therefore promoted from "v2 someday" to **the commercial centre of gravity**, with the founder's fintech domain knowledge as a genuine unfair advantage.

## 3. The Problem

Four failures define agent memory in mid-2026, each verified across practitioner reports, vendor documentation, and independent comparisons. **Session amnesia:** agents are stateless; teams re-explain architecture daily and agents rediscover the same gotchas on a loop. **Stale poisoning:** where memory exists nothing validates it, stale facts are served as truth, and the documented state of the art for hygiene is a manual monthly cleanup reminder. **Fragmentation:** Claude Code, Cursor, and Codex each keep machine-local, tool-siloed, mutually invisible memory on the same repositories. **Repo blindness:** the knowledge that matters most in real organisations lives between repositories — the platform team's gateway config, the Terraform repo gating deploys, the protobuf owned by another team — and single-repo memory is structurally unable to express it.

## 4. Market Position

The market splits into four camps, and the research confirmed the shape. General agent-memory platforms (Mem0 with ~48k stars and $24M raised, Zep/Graphiti, Letta, Cognee, EverMind, Hindsight, Supermemory) persist conversational memory with no code ground truth; their own comparison literature concedes invalidation "requires custom work," and their benchmark scores are self-reported and actively disputed. Coding-specific memory layers (ByteRover Cipher under Elastic 2.0, agentmemory, memories.sh) store without verifying. Code-intelligence graphs (CodeGraph, GitNexus, Serena, Qodo) model what the code *is* with no experiential memory. Native platform memory is single-tool, single-user, unverified. **Across all four camps, no product performs verification or invalidation of memories against code state. The verified-experience quadrant is confirmed unoccupied.** Zep's temporal invalidation is the nearest gesture, and it operates on conversational facts, not code.

Membook's position: the memory engine whose memories are checked against reality and reviewable by humans and auditors. Against native memory: cross-tool, team-shared, verified. Against memory platforms: anchored and auditable where they are floating and cloud-bound. Against code graphs: experiential where they are purely structural. Against Cipher specifically: genuinely MIT where they are Elastic, and verifying where they only store.

## 5. Core Concept and Data Model

The atomic unit is the **Memory**: a typed, anchored, provenance-carrying claim. Types — Decision, Gotcha, Convention, Map, Dead-end — matter because they retrieve and decay differently, and Dead-ends (captured failures: "tried X, failed because Y") are the highest-value, least-captured type in the industry. Each memory carries a distilled imperative statement, one or more anchors, a scope (repo, user, team), a status (verified, unverified, stale, invalidated), confidence and timestamps, full provenance (session, agent, model, source hash), and an optional supersession link forming a version chain.

The **anchor** is the invention: a pointer into checkable reality plus a change-detection strategy. In v1 anchors are git-shaped (repo, path, optional symbol, last-verified commit). Architecturally anchors are pluggable and graph-node-shaped from day one, because the research surfaced the git anchor's honest limitation: it catches code drift but is blind to dependency, API-schema, and configuration drift where anchored files are untouched. Closing that blind spot early — lockfile-hash anchors and API-contract anchors — is a committed roadmap item, not a someday, so that "verified" is never silently over-trusted.

The lifecycle is a five-stage pipeline. **Capture** (session exhaust via hooks, or an explicit MCP `remember` tool). **Distill** (end-of-session extraction into the schema, embedding-plus-judge deduplication, supersession on conflict, and aggressive rejection — retrieval precision, not storage cost, is the binding constraint, since a wrong retrieval costs a poisoned loop). **Anchor** (bind to what the session actually touched). **Verify** (diff HEAD against each anchor's last-verified commit at session start and on git hooks; unchanged anchors cost nothing, touched anchors get a cheap targeted re-check, then re-verify, flag stale, or invalidate — code-churn data supports roughly 3–8% of anchors touched per week in AI-heavy repos, keeping verification trivially cheap). **Retrieve** (a hard-capped ~2k-token boot pack of highest-value verified memories, in line with native loaders' own budgets and prompt-cache-friendly by stability, plus a mid-task `recall` tool ranked by vector, keyword, recency, and graph proximity to the files being touched).

**Secret scanning on the distillation path is launch-blocking, not optional.** Committed memory files are an exfiltration surface; Codex already redacts secrets from its memories for this reason, and a compliance-positioned product cannot ship without it.

## 6. Architecture

A local-first engine with no daemon: an MCP server spawned on stdio per session and a CLI (`membook init / status / review / verify / compact`). Files are the truth, the database is a cache: canonical memories live as markdown-with-frontmatter in a committed `.membook/` directory — diffable, PR-reviewable, merge-friendly, readable without the tool installed — while a disposable SQLite + sqlite-vec index (rebuildable via `membook reindex`) serves hybrid retrieval. Local embeddings (small ONNX model, fetched once, offline thereafter) with opt-in API fallback preserve the air-gap story. The stack: TypeScript on Node, pnpm monorepo (`@membook/core`, `@membook/mcp`, `membook` CLI, `@membook/spec` — the memory-file schema published as its own package so it can become a standard), plain git CLI for all diffing and rename tracking, provider-agnostic distillation (~100-line adapters, user's key or the agent's own model via a digest skill), vitest with a fixture-repo harness whose invalidation tests are the crown-jewel suite. The structural plane can consume an existing open-source code graph over MCP rather than rebuilding one; Membook owns the two defensible planes — experiential memory and verification.

**Instrumentation is a first-class feature from v0.1** — local-only telemetry logging hit rate, recall events, staleness catches, and (via session outcomes) wrong-path loops avoided. The research's sharpest criticism was that the ROI is unfalsifiable until measured; Membook ships measuring itself, and the published stale-memory-catch-rate benchmark versus Cipher, Mem0, and native memory becomes marketing no competitor can answer.

## 7. The Commercial Product: The Org Graph for Regulated Teams

Version two extends the graph across repository boundaries and is the business. Repositories are nodes; edges (consumes-API-from, deploys-via, imports-shared-lib-from, owned-by, gated-by) are auto-discovered from manifests, lockfiles, CI, and IaC, or declared. Memories anchor to edges and remote repos, yielding: **contract watch** (a producer schema change flips downstream consumers' memories stale before an agent writes broken code against it — and simultaneously closes part of the git anchor's blind spot); **ownership and process memory** (CODEOWNERS, catalogs, and PR history teach agents organisational reality so they stop proposing unmergeable changes); and **dependency-aware invalidation** (a breaking change in a shared library marks dependents' memories stale though their own files never changed).

The buyer is the regulated enterprise — financial services first. The deployment is self-hosted or air-gapped inside the customer's VPC, with RBAC on memory scopes, audit trails intrinsic to the data model, SSO, and query-level permission enforcement (a context engine is a blast-radius map in hostile hands; access control is architectural, not cosmetic). The pricing line is clean and principled: anything that runs on a laptop is free and MIT forever — stated as a public promise, and a weapon against Elastic-licensed and cloud-gated competitors — while anything requiring a server is commercial, because servers cost money to build and support. The free tool is distribution, credibility, and the standard; the server is revenue.

## 8. Economics (corrected)

The model: E[cost] = h·c_recall + (1−h)·c_rediscover, with c_recall ≈ 50 tokens and c_rediscover validated at 5–20k tokens against measured agent trajectories. Break-even reuse probability for writing a memory is ~3–6% — the most robust result in the model: a memory almost cannot fail to be worth writing; the constraint is retrieval precision. Verification costs thousands of tokens per week (git diffs are free; only touched anchors get LLM re-checks). The dominant term is poison avoidance: a stale memory consumed as truth triggers a wrong-path loop whose cost in tokens is large and whose cost in engineering time is the real number — and the time term dominates the token term by one to two orders of magnitude once prompt caching is priced in.

The honest ROI, for a 50-developer team, on a time-and-error basis at $100/hr loaded cost: pessimistic ~$33k/year (h=0.3, ~15 minutes of avoided wrong-path time per developer-week), expected ~$130k/year (h=0.6, ~30 minutes), optimistic ~$330k/year (h=0.8, ~75 minutes). Raw token savings contribute under $4k/year in every scenario and are excluded from the pitch. Sensitivity, in order: developer-time value × loops avoided (dominates), hit rate h (unproven until instrumented — hence instrumentation as a launch feature), staleness-catch efficacy (the differentiator), token pricing (negligible either way). All parameters are modelled, not measured; v0.1's telemetry exists to replace this table with data.

## 9. Roadmap

**v0.1 — Prove the loop (6–8 weeks).** MCP server (remember / recall / session_digest), SQLite + sqlite-vec, git anchoring with stale detection, committed `.membook/` files, CLI, secret scanning on write, instrumentation, tested on Claude Code and Cursor. The demo: an agent stores a gotcha; the anchored file is renamed; `membook status` reports one stale memory; the next session receives the corrected fact. No product on the market can run it.
**v0.2 — Quality, reach, and the blind spot.** Passive capture via hooks; distillation hardening; Codex, Windsurf, Cline; graph-provider integration for proximity retrieval; lockfile-hash and dependency anchors (first non-git verifiers); the published stale-catch benchmark.
**v1.0 — Team.** PR-reviewed team memories as the norm; merge conflict resolution; user-scope memory across projects; the public free-forever-core promise.
**v2.0 — Org graph (commercial).** Self-hosted server; cross-repo edges with auto-discovery; contract watch; ownership and process memory; RBAC, audit, SSO; fintech design partners recruited from the founder's own network.
**v3.0 — Beyond code.** Pluggable verifiers for documents, APIs, pipelines; the public registry of community memory packs (`membook add nextjs`); warm mid-task handoffs between agents.

## 10. Moats, Risks, and the Five Moves

**Moats:** the verification loop (architecturally unretrofittable by vector stores and code graphs alike, and confirmed absent from every competitor); the compliance-shaped file model regulated buyers require and cloud APIs cannot match; the compounding corpus of negative knowledge; genuine MIT against Elastic and cloud-gated rivals; instrumented, falsifiable claims in a category of marketing benchmarks; and, in act three, registry network effects.

**Risks, stated plainly:** distillation quality is unproven and is the product; the git anchor is an imperfect proxy for truth (mitigated by early non-git verifiers, never fully eliminated); the category is crowded, noisy, and better-funded (Mem0 $24M, Letta $10M, ~10,000 MCP servers of which a third fail to install); native platform memory absorbs the casual single-user market now; a solo or small team is racing funded incumbents and must hold the narrow scope to survive; committed memory files are a secret-leakage surface requiring scanning from day one; and every ROI number above is a model until the telemetry replaces it.

**The five moves, in order:** (1) the name is settled — Membook — register npm and domains immediately; (2) reframe every surface from token savings to prevented wrong-path loops and reclaimed hours, instrumented and falsifiable; (3) make git-anchored verification the entire marketing spine and publish the stale-catch benchmark no one else can enter; (4) aim the commercial product directly at regulated financial services with the audit-ready story and secret scanning as table stakes; (5) close the git anchor's blind spot early with dependency and contract verifiers so "verified" stays honest.
